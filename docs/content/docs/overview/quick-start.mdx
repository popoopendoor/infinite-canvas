# Quick Start

The OAuth and `money` billing flow requires the Docker stack: Nginx serves `web/` and proxies same-origin requests to the Node.js BFF.

## Deploy with Vercel

Vercel can still build the static `web/` frontend, but it does not run the BFF and therefore cannot satisfy the OAuth and billed-model deployment described here. Use Docker for the complete stack.

## Run locally

```bash
git clone git@github.com:popoopendoor/infinite-canvas.git
cd infinite-canvas/web
bun install
bun run dev
```

Open `http://localhost:3000`.

## Run with Docker

```bash
cd ..
cp .env.example .env
# Edit .env with the required integration settings.
docker compose -f docker-compose.local.yml up -d --build
```

## First-time setup

- Register the exact `/auth/callback` URL in Flarum OAuth and install/configure the separate Canvas Money Bridge.
- An operator publishes models and fixed prices in the BFF `MODEL_CATALOG_JSON` and maps managed provider keys in `MODEL_PROVIDER_KEYS_JSON`. After login, those models appear automatically in the `Canvas managed` provider; users do not need to enter a provider key. Requests hold the current Flarum `money` balance before execution, capture on success, and release on a definite failure.
- BYOK remains available: publish the model without a server key, then enter its `Base URL` and `API Key` in Settings. The browser encrypts the key for that request, and BYOK requests use the same billed BFF path.
- Open `/prompts` to fetch prompt repositories directly from the browser and cache them in IndexedDB.
- Configure WebDAV if you want to synchronize canvases, assets, and generation history across devices.

Canvas projects and My Assets are primarily stored in the browser. The BFF owns OAuth, published models, and billing; the browser does not receive OAuth or bridge tokens.
